# Blue3 共享录分部署说明

服务器电脑保存唯一的数据库, 其他电脑通过客户端录分. 客户端提交使用现有多人计分逻辑, 保存后会显示在服务器原有的比赛记录、排行榜和技术统计中.

## 服务器电脑

1. 关闭原来运行计分工具的命令行窗口.
2. 将新版 `vibe-scoreboard` 文件夹中的程序文件复制到原程序目录, 覆盖同名文件. 保留原来的 `data` 文件夹, 尤其是 `data/scoreboard.sqlite3`. 更新包不含数据库.
3. 双击 `start-server.bat`. 服务器需要 Python 3.10 或更新版本, 与原版要求相同.
4. 在 Windows 防火墙提示中允许 Python 在当前使用的私人网络通信. 如果没有弹窗且其他电脑无法连接, 在防火墙入站规则中允许此程序或 TCP 8766 端口.
5. 启动窗口会显示客户端地址及录分码. 将这两项发给参与者, 并保持服务器及启动窗口运行.

地址示例: `http://192.168.1.100:8766`. 地址中的 IP 应是服务器电脑的实际局域网 IPv4 地址, 可以用 `ipconfig` 查看. `0.0.0.0` 是监听设置, 不能作为客户端连接地址; 其他电脑也不能填写服务器的 `127.0.0.1`.

管理页面仍从服务器本机的 `http://127.0.0.1:8765` 打开, 用于建立赛季、管理选手、查看统计、修改记录和备份. 共享录分端口用于客户端查询名单和提交成绩, 不提供删除、数据库下载或管理界面.

不要同时运行 `start.bat` 和 `start-server.bat`, 两者默认都会使用本机管理端口 8765. 使用共享服务器时不再需要另外启动 `start.bat`.

服务器默认沿用原程序目录中的数据库. 如需指定另一个数据目录:

```bat
python server.py --data-dir "D:\Blue3Data"
```

该目录内的数据库文件名应为 `scoreboard.sqlite3`. 第一次启动会生成 `entry-access.json`, 用于保存录分码和服务器标识. 保留此文件后重启服务器, 录分码不会改变.

## 参与者电脑

客户端适用于 Windows 10/11 64 位. 不需要安装 Python、Go 或 Node.js.

1. 双击 `Blue3-ScoreEntry.exe`, 它会自动打开默认浏览器中的专用录分页面.
2. 填入服务器地址和录分码, 点击连接. 客户端会记住服务器地址; 完全退出后重新打开, 需要再次填写录分码.
3. 选择所属赛季, 选择本场选手, 填写每人的半庄数和分数. 可以添加超过三人的对局.
4. 核对分数合计为 0, 点击提交本场成绩. 页面显示记录编号后表示已经写入服务器.
5. 下一场点击新建下一场. 使用完毕时, 点击右上角退出客户端, 然后关闭网页.

客户端 1.3.0 的新增成绩固定使用 rate 1, 不显示倍率输入栏; 半庄数默认 1, 仅累计对战数量, 不再乘到分数上. 主机管理页面原有的倍率设置保持不变.

分数最多两位小数. 半庄数接受 0 到 1,000,000 的整数, 已单独汇总过数量的历史成绩可填写 0. 未填写完整、重复选择同一选手、半庄数无效或者分数合计不为 0 时不能提交.

一次提交对应一条多人对局记录. 例如填入 8 局, 对战数量增加 8, 同桌场数仍只增加 1. 同一场由一位录分者统一提交, 不要让每位选手各自重复提交整场.

客户端 1.3.0 只选择已有赛季和选手, 不提供新增赛季或选手的入口. 请由主机管理员维护名单, 客户端点击“刷新名单”即可读取最新内容. “增加录分行”仅用于在本场选择已有选手.

更新前请先完成或确认未完成的提交, 在旧页面右上角点击“退出客户端”, 再打开新版 EXE. 页面显示“客户端 1.3.0”用于确认版本. 新版检测到旧客户端仍在运行时会提示先退出旧版.

## 网络中断与重试

如果提交时断线, 页面会保留原提交并提供重试上次提交. 重试沿用原提交标识, 后端不会重复创建同一条记录. 在确认前, 当前录分内容保持锁定.

客户端完全退出后, 未确认的提交仍保存在本机. 再次打开并连接原服务器后, 可以继续重试. 服务器明确拒绝的无效成绩则可直接修改后重新提交. 升级前已经存在的未确认提交会保留原始内容及倍率用于重试, 确认后的新成绩统一使用倍率 1.

地址设置及未确认提交保存在 `%APPDATA%\Blue3-ScoreEntry`. 此处不保存后台数据库或录分码. 提交成功后会删除本次未确认记录.

## 不在同一局域网时

当前程序提供共享录分服务, 不会自动建立公网通道. 外网电脑需要能够访问服务器, 例如通过已有的 VPN、内网穿透或已配置的公网入口.

客户端支持 HTTP 和 HTTPS 地址. 局域网可以直接使用 HTTP 地址; 公网入口应使用 HTTPS. 录分码在客户端请求中用于验证访问权限, 不会出现在 URL 中.

有域名证书时, 可以直接给录分服务启用 HTTPS:

```bat
python server.py --tls-cert "C:\certs\fullchain.pem" --tls-key "C:\certs\privkey.pem"
```

也可以通过 HTTPS 反向代理转发到录分端口 8766. 只转发录分端口即可, 本机管理端口 8765 保留本机访问.

服务器休眠、关机或网络断开时, 其他电脑无法提交. 服务器局域网地址变化后, 客户端需要更新地址; 可在路由器中为服务器保留固定的局域网 IP.

## 开发与验证

服务器和原程序均只使用 Python 标准库:

```bash
python -m unittest discover -s tests -v
node tests/test_frontend.js
```

客户端源码在 `client` 中, 运行时不需要第三方库. 使用 Go 1.24 或更新版本:

```bash
cd client
go test ./...
```

Windows 下运行 `client/build-windows.bat` 生成 exe. 在 Linux 下交叉编译:

```bash
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -buildvcs=false -trimpath -ldflags "-s -w -H windowsgui" -o Blue3-ScoreEntry.exe .
```

可选前端交互检查使用 jsdom:

```bash
cd client
npm install
npm test
```

验证包含真实 HTTP 录分、原管理页面读取、数据库统计、并发客户端、重复重试、服务重启后的数据保留、客户端重启后的未确认提交恢复, 以及录分页面交互. 客户端 1.3.0 的验证包含固定倍率、移除客户端新增操作、旧提交原样重试和版本标识. Windows EXE 可使用 `python client/integration_test.py --client 路径` 在临时数据库上验证多人录分、固定倍率和断线恢复.
